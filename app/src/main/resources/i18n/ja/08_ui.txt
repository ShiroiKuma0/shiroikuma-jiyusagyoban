# UiCustomizationScreen.kt — 「文字認識」 OCR section
= High-accuracy model
: 高精度モデル
= On: PP-OCRv5 server (81 MB). Off: mobile (16 MB), about 2.5x faster — roughly 2 s instead of 5 s on a full-width screenshot. Measured on clean screenshot text the two are equivalent; the server model's headroom is for photographed and handwritten text. Japanese and English only — there is no server-sized Latin or Cyrillic recogniser, so those chips are unaffected.
: オン：PP-OCRv5 server（81 MB）。オフ：mobile（16 MB）で、約2.5倍速くなります。全幅のスクリーンショットで5秒かかるところが2秒ほどです。きれいなスクリーンショットの文字では、測定したかぎり両者の精度は同じです。serverモデルの余力が生きるのは、撮影した文字や手書きの文字です。日本語と英語だけが対象です。ラテン文字とキリル文字にはserver規模の認識モデルがないため、それらのチップには影響しません。
= Models
: モデル
= The recognition weights are about 100 MB and never change, so they are NOT in the APK — every kept build would have carried another copy. Fetch them once, point each row at the file, and they stay. The character dictionaries do ship, because each one has to match its model exactly.
: 認識用の重みファイルは約100 MBあり、内容が変わることもないため、APKには入れていません。入れると、保存しておくビルドごとに同じものがもう一つ増えてしまうからです。一度だけ取得して、各行でそのファイルを指定すれば、そのまま使い続けられます。文字辞書はAPKに同梱しています。それぞれがモデルと正確に一致していなければならないためです。
= Detection
: 検出
= Detection long side
: 検出時の長辺
= The size the detector actually sees. 1600 px is measured, not inherited — against PP-OCR's own 960 default it halved the character error on a full-width screenshot, and the errors it removed were exactly the small text. Higher costs time with the area.
: 検出器が実際に見る大きさです。1600 pxは引き継いだ値ではなく、測定して決めた値です。PP-OCR本来の既定値960と比べると、全幅のスクリーンショットで文字の誤りが半分になり、減ったのはまさに小さな文字の誤りでした。大きくすると、面積に比例して時間がかかります。
= Binarisation threshold
: 二値化のしきい値
= Where the probability map becomes text. Lower finds fainter text and starts joining neighbouring lines into one box; higher splits words off the ends of lines.
: 確率マップのどこからを文字とみなすかを決めます。下げると薄い文字も見つかりますが、隣り合う行が一つの枠にまとまり始めます。上げると、行の端の単語が切り離されます。
= Box score threshold
: 枠のスコアのしきい値
= The confidence a detected region needs to survive. Raising it drops marginal boxes — useful on a noisy photograph, and a good way to lose real faint lines on a clean screenshot.
: 検出した領域を残すために必要な確信度です。上げると、きわどい枠が捨てられます。ノイズの多い写真では役に立ちますが、きれいなスクリーンショットでは、本物の薄い行まで失いやすくなります。
= Unclip ratio
: 枠の拡張率
= How far each detected box is grown before the crop is taken — the one to leave alone without a test image in front of you. Detection predicts a SHRUNK region, and this is what puts the ascenders and diacritics back inside it: too low silently decapitates every line and 'ä' starts reading as 'a'. Too high swallows the line above. 1.5 is PaddleOCR's own value and measured correct here.
: 切り抜く前に、検出した枠をどれだけ広げるかを決めます。確認用の画像が手元にないときは、触らないほうがよい設定です。検出が予測するのは縮めた領域で、文字の上に突き出た部分や発音区別符号を枠の中に戻すのがこの値です。低すぎると、何の知らせもなくすべての行の上端が切れ、「ä」が「a」と読まれるようになります。高すぎると、上の行まで取り込んでしまいます。1.5はPaddleOCR本来の値で、ここでも測定して正しいと確かめてあります。
